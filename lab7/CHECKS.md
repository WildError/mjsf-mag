## Діагностичні зміни за завданням

- Для Offline-відновлення тимчасово змінити /auth/me на /auth/me?delay=1500
  у stores/auth.js. При початку GET увімкнути Offline. Після перевірки повернути адресу.
- Для затримки PATCH тимчасово додати ?delay=1500 до адреси PATCH у stores/products.js.
  Почати збереження та натиснути «Вийти». Потім прибрати затримку.
- Для 401 у api/http.js тимчасово після формування headers додати:
  if (path.startsWith('/auth/products')) headers.Authorization = 'Bearer invalid'
  Значення токена у store не змінювати. Після перевірки видалити діагностичний рядок.
- Для підробленого збереженого токена змінити значення lab7.accessToken
  у DevTools → Application → Session Storage на invalid та оновити сторінку.

## Скриншоти для звіту

1. Форма входу (поле пароля порожнє).
2. Приватний список із профілем у шапці.
3. Редактор товару та хлібні крихти.
4. Помилки валідації.
5. Повідомлення про успішне збереження та оновлена назва.
6. Перевірочні розміри екрана.
7. Network зі статусом і кількістю POST/PATCH, без значень паролів і токенів.
8. Успішний npm run build.

На знімках сторінок залишити адресний рядок і, коли можливо, підвал із даними автора.
Не відкривати вкладки Payload/Headers із секретними значеннями під час знімка.
