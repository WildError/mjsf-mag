## Маршрути

| Адреса | Ім’я | Доступ |
| --- | --- | --- |
| / | redirect products | Публічний |
| /products | products | Публічний каталог |
| /products/:id | product-overview | Публічний огляд |
| /products/:id/reviews | product-reviews | Публічні відгуки |
| /about | about | Публічний |
| /login | login | Публічна форма входу |
| /manage/products | manage-products | Приватний список |
| /manage/products/:id/edit | manage-edit | Приватний редактор |
| Невідома адреса | not-found | Сторінка 404 |

/manage/products використовує ManageLayout із meta.requiresAuth: true.
Порожній дочірній шлях показує список; :id/edit — редактор.
Крихта оболонки «Керування», крихта редактора — підтверджена назва товару.
Порожні дочірні маршрути не додають дублікатів.

## Життєвий цикл сеансу

1. beforeEach очікує auth.restore(). Без токена встановлюється guest без HTTP.
2. Збережений токен перевіряється GET /auth/me. Одночасні виклики restore
   очікують один Promise; наступні переходи використовують підтверджений результат.
3. За 401 токен вилучається. Мережева помилка встановлює unavailable:
   токен залишається для повторної перевірки, приватний вміст закритий.
4. Гість перенаправляється на /login?redirect=... . Після POST /auth/login
   приймаються лише внутрішні цілі, зіставлені з manage-products або manage-edit.
   Перехід виконується через replace.
5. Приватні запити й PATCH ідуть через auth.request з поточним Bearer.
   401 очищує лише той сеанс, для якого запит було розпочато.
6. Вихід скасовує операції, очищує профіль, токен і словник змін.
   Звичайний вихід веде в каталог; 401 — до входу. Гард чернетки цьому не заважає.
7. Ідентифікатори операцій, версія сеансу й AbortSignal не дозволяють запізнілим
   відповідям повернути старий стан або змінити новий сеанс.

Ключ sessionStorage: lab7.accessToken. Пароль і refreshToken не зберігаються.
Автоматичного оновлення токена немає; після завершення його строку потрібен новий вхід.

## Редагування

Редагуються лише title, price, stock, description.
Назва після trim — 1–120 символів; опис — 1–2000.
Ціна — скінченне число більше 0; залишок — ціле число від 0.
Порожні числові поля відхиляються. Помилки пов’язані з полями через
aria-describedby та aria-invalid; фокус переходить до першого некоректного поля.
Невалідна форма не надсилає PATCH.

Під час збереження поля й повторне надсилання заблоковані.
Помилка лишає чернетку; «Скасувати зміни» відновлює підтверджені значення без запиту.
onBeforeRouteLeave, onBeforeRouteUpdate і beforeunload захищають незбережений ввід.
Обробник beforeunload вилучається після демонтування.

Після успішного PATCH store записує лише чотири підтверджені поля за id.
displayProduct поєднує їх із GET-даними для приватного списку, публічної сторінки,
крихт і карток каталогу. До відповіді API спільні дані не змінюються.

## Межі навчальної моделі

DummyJSON імітує PATCH, але не зберігає зміни на сервері.
Локальний словник живе тільки в пам’яті й очищується при reload або виході.
Після reload збережений токен перевіряється повторно, а товари мають серверні значення.
Серверний пошук працює з початковими даними; локальні назви не змінюють склад видачі.

sessionStorage доступне JavaScript і не є захистом від XSS.
Гард контролює інтерфейс, але не замінює авторизацію API.
Локальний вихід не відкликає вже виданий токен на сервері.
Це навчальна модель, а не готова система авторизації для виробничого сервісу.

## Перевірки та збірка

```cmd
npm test
npm run build
npm exec vite preview -- --port 5177 --strictPort
```

У комплекті 9 тестів Node.js із контрольованими відповідями API:
валідація, блокування повторного входу, restore і його повтор,
пізні відповіді, PATCH, 401, скасування приватного читання й дозволені redirect.
Вони не звертаються до реального сервера.

Тести та збірку виконано під час підготовки архіву. Додатково пройшла перевірка зібраного застосунку в DOM-емуляції з тестовим API: вхід, валідація та фокус, скасування чернетки, захист переходу, збереження, оновлення публічних і приватних представлень та вихід. Візуальні перевірки й роботу
з живим API потрібно підтвердити у браузері користувача:
автоматичний браузер у середовищі підготовки не запустився,
а пробний запит входу до DummyJSON повернув HTTP 403.
Це не підмінено твердженням про успішний живий вхід.

Таблиця сценаріїв — CHECKS.md. Фактичні результати ручних перевірок залишено
для заповнення після виконання. Скриншоти створюються з реального запуску.

createWebHistory потребує налаштування сервера: маршрути застосунку мають
повертати index.html. Vite preview перевіряє локальну збірку, не публікує сайт.
