Виконав: Коцур Валерій
Група: F2.25-2-з

## Розподіл відповідальності

|Модуль|Відповідальність|
|-|-|
|App.vue|Загальні шапка, навігація, підвал і зовнішній RouterView|
|ProductsLayout.vue|Оболонка розділу товарів із вкладеним RouterView|
|ProductCatalogView.vue|Пошук, запити каталогу та накопичення сторінок|
|ProductLayout.vue|Завантаження одного товару за id, спільні дані огляду та відгуків|
|ProductOverviewView.vue|Відображення огляду отриманого товару|
|ProductReviewsView.vue|Відображення відгуків або порожнього стану|
|AboutView.vue|Інформація про застосунок|
|NotFoundView.vue|Сторінка для невідомої адреси|
|Breadcrumbs.vue|Відображення переданих хлібних крихт|
|useBreadcrumbs.js|Побудова крихт за route.matched і назвою товару|
|router/index.js|Конфігурація маршрутів і режим історії|

Компоненти каталогу та composables із лабораторної №5
повторно використовуються в новому проєкті.

## Ієрархія маршрутів

|Батьківський маршрут|Шлях|Компонент|Ім’я маршруту|
|-|-|-|-|
|—|/|Перенаправлення на /products|—|
|—|/products|ProductsLayout|—|
|/products|Порожній дочірній шлях|ProductCatalogView|products|
|/products|:id|ProductLayout|—|
|/products/:id|Порожній дочірній шлях|ProductOverviewView|product-overview|
|/products/:id|reviews|ProductReviewsView|product-reviews|
|—|/about|AboutView|about|
|—|/:pathMatch(.*)*|NotFoundView|not-found|





\## Запуск і збірка



npm ci

npm run dev -- --port 5176 --strictPort

npm run build



\## Маршрути



\- / — перенаправлення на каталог.

\- /products — каталог із пошуком.

\- /products/:id — огляд товару.

\- /products/:id/reviews — відгуки про товар.

\- /about — інформація про застосунок.

\- Невідомі адреси — сторінка 404.



\## Стан і навігація



Параметр маршруту id визначає товар, а параметр запиту q зберігає

пошуковий запит. Дані товару завантажуються в ProductLayout

і передаються дочірнім сторінкам через props. Перехід між оглядом

і відгуками не потребує повторного завантаження товару.



Хлібні крихти формуються з route.matched і meta.breadcrumb.

Назва товару оновлюється після отримання даних з API.



\## Розгортання



Використовується createWebHistory. На сервері потрібно налаштувати

повернення index.html для маршрутів застосунку, щоб пряме відкриття

та оновлення вкладених адрес працювали.
